## 应先定位的科学问题

建议先围绕这个**待确认的问题**继续调查：

> 在总训练 token、模型规模、验证信息和调度开销可比的条件下，多数据集 SFT 中，哪些更新会提升一类能力却损害另一类能力？现有配比、过拟合控制和软目标方法之后，是否仍有稳定、重要的剩余问题？

这是问题定位，没有宣称找到新方法或证实新机制。当前尤其要区分：

- 数据量失衡，与不同数据集的学习速度和过拟合时点；
- 同一能力被不同数据源重复监督，与不同能力之间的更新冲突；
- 训练域收益，与其他域及域外任务的能力保留；
- 真正的数据调度收益，与多用 token、额外验证或重启训练带来的收益。

训练顺序、梯度冲突、Adam 状态和低秩空间也需要继续检查相邻工作；不能仅凭给机制换一个名字判断原创性。

## 已经检查的实际实现

mSFT 的官方代码包含训练、检查点排除与评测逻辑；其 README 默认配置是 4 张 RTX 3090，不能直接作为本项目的单卡运行配置。

IDEAL 的入口包含 DDP/K-FAC 计算，重采样脚本使用示例影响值与本地路径。作为比较方法，需要完整连接实际影响值、训练和原生评测，而不是照搬示例数值。

OP-Mix 的源码包含 LoRA 合并和多个阶段的控制逻辑。它搜索的成本、评测成本及模型驻留内存，都要和最终训练一起计入。

SoFT 已核查方法与评测章节。本轮未在其论文页面确认对应的作者代码入口，复现状态保持待补齐。

## 公开数据与评测的起点

已检查 Tulu 3 mixture 的发布者数据卡：保留 id、messages 和 source，可追踪不同数据来源。本项目需要同时区别“来源标签”和“能力标签”，不能假定一个来源只训练一种能力。

已检查 lm-evaluation-harness 中 GSM8K 的数据 split、抽取与 exact-match 配置，以及 IFEval 的严格/宽松、prompt/instruction 四类指标实现。**IFEval 发布 split 名为 train，但在该评测中承担测试用途，不能因此把它当作训练数据。**

mSFT 的十任务设定可作为另一条公开多任务比较路径。代码任务的 EvalPlus/MBPP+/HumanEval+、跨域泛化和其他既有数据集还需要进一步读取原生评测；最终覆盖矩阵目前没有冻结。

## 单卡资源判断

初步考虑先审查 0.5B 级模型的全参数训练，以及 1.5B–1.7B 级模型的 LoRA 方案；这是容量上的规划建议，尚无本机峰值和速度数据。

2080 Ti 是 Turing 架构。当前 FlashAttention-2 主路径面向 Ampere/Ada/Hopper，发布者另有 Turing 子集实现。默认方案应从 FP16 与本机支持的注意力实现出发，先让 Local 校准，不能套用 H100 的 BF16 配方。依据：[FlashAttention 作者文档](https://github.com/Dao-AILab/flash-attention)。

一张卡上先按一个 GPU 训练/评测任务管理；CPU 数据准备可在实际 RAM、I/O 和依赖允许时并行。batch size、序列长度、梯度累积和数据加载参数需要 Local 测得稳定吞吐后决定。
